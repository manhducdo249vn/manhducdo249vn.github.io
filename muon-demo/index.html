Things to try

  1. Switch Embeddings to Coupled. GD and Muon do not change at all; Adam does. Rotating the embeddings rotates the gradient. Orthogonalization commutes with rotations, sign() does not.
  2. With Coupled embeddings, set Frequent classes to Scattered. Adam becomes almost as unbalanced as GD.
  3. Switch Muon to 5-step Newton–Schulz, the version used in practice. It is less balanced than exact orthogonalization, but far more balanced than GD.
  4. Move α down to 20%. Every class is now equally frequent, and GD becomes balanced too: its imbalance comes only from the class frequencies.

Why it happens

At W = 0 with decoupled embeddings, the gradient has a closed form:

G = (1/K)·1πᵀ − diag(π)
  • GD steps along −G, which moves class k in proportion to its frequency πk. Rare classes lag.
  • Adam (sign-GD) steps along sign(−G) = 2I − J. Every class gets the same push, but only in this coordinate system.
  • Muon steps along the orthogonal factor of −G, which is close to I − J/K. Every class gets the same push in any coordinate system.

Setup

Section 5 and Appendix D of Wang et al., Muon Outperforms Adam in Tail-End Associative Memory Learning (ICLR 2026). K = 45 instead of 999, β = 0.2, W₀ = 0, orthonormal embeddings, and the paper's 3×3 rotation blocks for the coupled case. Adam is sign-GD (β₁ = β₂ = 0) and Muon has no momentum, as in the paper. Every update is rescaled to the same Frobenius norm, so the optimizers differ only in direction, and classes are compared at equal average loss rather than at equal step.
